# dhnt/site

The content and renderer of the dhnt company pages: home (`/`) and About
(`/about`), published at <https://ai.dhnt.io>. It is the first `<owner>/site`
repository: every site owner gets one, generated from the same bashy
template (`examples/shaping/site/site.bsh` in
[qiangli/bashy](https://github.com/qiangli/bashy)). Nothing in the template
is dhnt-specific; everything dhnt-specific lives here.

## What is here

| Path | What |
|---|---|
| `content/home.md`, `content/about.md` | The page source: front matter (`title`, `path`, `summary`, `sections`) and one `## Heading {#id}` per declared section |
| `site.json` | Site title, `origin` (`https://ai.dhnt.io`), `owner`, shared navigation Home / About / GitHub |
| `skills/dhnt-site/SKILL.md` | How an agent reads these pages: negotiation, twins, revision, citation |
| `LICENSE`, `NOTICE` | Code under Apache-2.0; page content (c) DHNT Inc. |

Generated by `site.bsh init` (see [Status](#status)): the stdlib Go library
`package site` (`render.go`, `server.go`, `check.go`), the `cmd/server`
binary, `shaped.json`, `contract.bsh` and `checks/`.

## Content contract

- Section ids are **declared** in the front matter `sections` list and on
  each heading as `{#id}`; they are never derived from heading text, so a
  copy edit to a heading keeps its anchor.
- Home: `#what`, `#start`, `#shape`. About: `#about`, `#team`, `#contact`.
- One content document renders three ways, which list the same links and
  section ids: an HTML fragment (`/`, `/about`), Markdown (`/index.md`,
  `/about.md`) and JSON (`/index.json`, `/about.json`):
  `{path, title, summary?, revision, nav:[{label, href}], sections:[{id, heading, html, markdown, sha256}]}`.
- The front matter `summary` is one lead paragraph: it renders under the
  title in HTML and Markdown, appears as `summary` in JSON, and counts as
  content, so editing it changes the revision.
- **Revision** = short SHA-256 of the canonical content document: a copy
  change changes it, a rendering change does not. `sections[].sha256` hashes
  each section on its own.

## How it is consumed

1. **Live.** The hosted plane imports this module at a pinned version and
   serves `/` and `/about` from it: server-rendered content and shared nav,
   `Accept` negotiation (`text/markdown`, `application/json`, else HTML), the
   `.md`/`.json` twins, `Vary: Accept`, `ETag` = revision, `Link` alternates,
   `robots.txt` and `llms.txt`. The browser application renders the same
   JSON, so there is one text, not two.
2. **Shaped app.** The same repository registers on the owner's engine host
   as a `bashy shape` app. The owner wishes a copy change against a section
   at a revision; the candidate preview serves the same three
   representations at the candidate revision; approve and undo are
   `bashy shape` verbs. Publishing an approved candidate live is a pull
   request here, a pin bump and a hosted-plane release.

## Citing a section

```json
{"url": "https://ai.dhnt.io/about#team", "section_id": "team",
 "revision": "<page revision>", "section_sha256": "<sections[].sha256>",
 "quote": "<exact text>"}
```

Human form: `https://ai.dhnt.io/about#team @ <revision>`.

## Status

Assembled and released as `v0.1.0`. The renderer, server, library and
shaped-app face were generated from the bashy site template at
[qiangli/bashy](https://github.com/qiangli/bashy) `7473e814`
(`examples/shaping/site/site.bsh`), over the content authored here:

```sh
bashy --bashsharp <bashy>/examples/shaping/site/site.bsh \
    init . --title DHNT --origin https://ai.dhnt.io --owner dhnt \
    --module github.com/dhnt/site
```

`init` keeps existing files, so the content, `site.json`, skill, README,
`LICENSE` and `NOTICE` are authored here and the template supplies only the
machinery. To re-render or re-check after a copy edit:

```sh
bashy --bashsharp <bashy>/examples/shaping/site/site.bsh render . --format md /about
bashy --bashsharp <bashy>/examples/shaping/site/site.bsh check .
GOWORK=off go build ./... && GOWORK=off go test ./...
```

Nothing but the Go standard library is required: `go.mod` declares no
dependency, and `TestStandaloneDeps` fails the build if one appears.

### How the hosted plane imports it

The repository root is importable `package site`, and `site.json` plus
`content/*.md` are embedded in the module (`site.Assets`), so a consumer
needs no checkout of this repository:

```go
import "github.com/dhnt/site"

s, err := site.LoadEmbedded()        // or site.Load(dir) / site.LoadFS(fsys)
if err := site.Validate(s); err != nil { /* structural checks */ }
s.SetOrigin("https://ai.dhnt.io")    // deployment origin; never affects a revision
http.Handle("/", site.NewHandler(s)) // negotiation, twins, headers, robots.txt, llms.txt
```

The hosted plane pins a released version (`go get github.com/dhnt/site@v0.1.0`)
and serves `/` and `/about` from it, so the live pages and this repository
cannot drift. `Page.Revision` is the published `ETag`; because it digests
canonical content only, redeploying the same content keeps the same revision.
`cmd/server` builds the same routes as a standalone binary and doubles as the
check runner (`-check all`, `-render PATH -format html|md|json`).

### How an owner shapes it

The repository is also a `bashy shape` app (`shaped.json`,
`server.main: "cmd/server"`), registered on the owner's engine host:

```sh
bashy app add dhnt-site --type shaped --source <checkout> --label "DHNT Site"
bashy shape wish dhnt-site "<copy edit>" --page /about \
    --element 'section=team revision=<observed revision>'
bashy shape verify dhnt-site <candidate>
```

A wish carries the section id and the revision the owner actually read. The
verifier runs the frozen `checks/` from the base commit in a scrubbed
environment: `render-determinism` (two renders byte-identical, and all three
representations listing the same links and section ids), `unique-ids`,
`links-resolve`, and `stale-base`, which refuses a wish written against a
superseded revision with `stale, re-read`. A verified candidate previews at
its own new revision in all three representations; `approve` and `undo` are
`bashy shape` verbs, and the live page's `ETag` only moves when an approved
candidate lands here, its pin is bumped, and the hosted plane is released.

## Optional DNS TXT

Publish an optional DNS TXT record at `_agents.<host>` so agents can discover
the site without fetching it first:

```text
_agents.<host>  TXT  "v=agents1; index=https://<host>/agents.txt; mcp=https://<host>/mcp"
```

The record is advisory only; `/agents.txt` remains the canonical entry point.

# dhnt/site

The content and renderer of the dhnt company pages: home (`/`) and About
(`/about`), published at <https://ai.dhnt.io>. It is the first `<owner>/site`
repository: every site owner gets one, generated from the same bashy
template (`examples/shaping/site/site.bsh` in
[qiangli/bashy](https://github.com/qiangli/bashy)). Nothing in the template
is dhnt-specific; everything dhnt-specific lives here.

## What is here

| Path | What |
|---|---|
| `content/home.md`, `content/about.md` | The page source: front matter (`title`, `path`, `summary`, `sections`) and one `## Heading {#id}` per declared section |
| `site.json` | Site title, canonical origin (`https://ai.dhnt.io`), shared navigation Home / About / GitHub |
| `skills/dhnt-site/SKILL.md` | How an agent reads these pages: negotiation, twins, revision, citation |
| `LICENSE`, `NOTICE` | Code under Apache-2.0; page content (c) DHNT Inc. |

Generated by `site.bsh init` (see [Status](#status)): the stdlib Go renderer
and server, `shaped.json`, `contract.bsh` and `checks/`.

## Content contract

- Section ids are **declared** in the front matter `sections` list and on
  each heading as `{#id}`; they are never derived from heading text, so a
  copy edit to a heading keeps its anchor.
- Home: `#what`, `#start`, `#shape`. About: `#about`, `#team`, `#contact`.
- One content document renders three ways, which list the same links and
  section ids: an HTML fragment (`/`, `/about`), Markdown (`/index.md`,
  `/about.md`) and JSON (`/index.json`, `/about.json`):
  `{path, title, revision, nav:[{label, href}], sections:[{id, heading, html, markdown, sha256}]}`.
- **Revision** = short SHA-256 of the canonical content document: a copy
  change changes it, a rendering change does not. `sections[].sha256` hashes
  each section on its own.

## How it is consumed

1. **Live.** The hosted plane imports this module at a pinned version and
   serves `/` and `/about` from it: server-rendered content and shared nav,
   `Accept` negotiation (`text/markdown`, `application/json`, else HTML), the
   `.md`/`.json` twins, `Vary: Accept`, `ETag` = revision, `Link` alternates,
   `robots.txt` and `llms.txt`. The browser application renders the same
   JSON, so there is one text, not two.
2. **Shaped app.** The same repository registers on the owner's engine host
   as a `bashy shape` app. The owner wishes a copy change against a section
   at a revision; the candidate preview serves the same three
   representations at the candidate revision; approve and undo are
   `bashy shape` verbs. Publishing an approved candidate live is a pull
   request here, a pin bump and a hosted-plane release.

## Citing a section

```json
{"url": "https://ai.dhnt.io/about#team", "section_id": "team",
 "revision": "<page revision>", "section_sha256": "<sections[].sha256>",
 "quote": "<exact text>"}
```

Human form: `https://ai.dhnt.io/about#team @ <revision>`.
